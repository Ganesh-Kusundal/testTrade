# kanban.cli — project state board

`kanban.cli` is the project's **state board**: one source of truth for
what's in flight, blocked, broken, and planned. It lives in
`.kanban/state.json` and renders `.kanban/BOARD.md` automatically.
Full skill doc at `.qoder/skills/kanban.cli/SKILL.md`.

```bash
python3 .qoder/skills/kanban.cli/scripts/kanban.py <command>
```

Works with any bare `python3 ≥ 3.11` — no venv, no pip installs.
Complements `/graphify`: graphify answers "how does X work?";
kanban answers "what's the status of X?"

## Session starts (agents and developers)

1. Run `python3 .qoder/skills/kanban.cli/scripts/kanban.py status`
   (or read `.kanban/BOARD.md` directly).
2. If the graphify section shows **STALE**, run `/graphify update`.
3. Review in-progress cards, blocked cards, open bugs, high risks.

## Status updates

1. **Starting work** — `card move <K-NNN> in_progress`.
2. **Hitting a blocker** — `card move <K-NNN> blocked --note "reason"`.
3. **Finishing work** — `card move <K-NNN> done`.
4. **After any code change** — run `scan`, then update touched cards
   and set purposes for new files.
5. **End of session** — run `sync-tracker` and paste the output into
   your progress log.

## Quick reference

| I want to… | Command |
|---|---|
| See project state | `status` or read `.kanban/BOARD.md` |
| Refresh facts | `scan` |
| Add a task/bug/debt | `card add "title" --kind bug --priority P1` |
| Move a card | `card move K-001 in_progress` |
| Show a card | `card show K-001` |
| List cards | `card list --lane in_progress` |
| Set file purpose | `file set-purpose scalpr/runtime/boot.py "..." `
| Check integrity | `check` |
| Show stale items | `stale` |
| Get sync block | `sync-tracker` |
| Run self-test | `check --selftest` |

## Rules

- Never edit `.kanban/state.json` or `.kanban/BOARD.md` by hand —
  both are regenerated by the CLI. Curated prose (component
  descriptions, flows) is added via `component add` / `flow add`.
- Never invent card IDs — `card add` allocates and validates them.
- Machine-readable data comes from `status --json` or `check --selftest`,
  not from parsing `BOARD.md`.
- Historical tasks (57 legacy tasks, all done) are preserved in
  `.kanban/board.legacy.json` for reference.
